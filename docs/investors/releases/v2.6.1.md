## What this release is

Defects found by reading the code and the pack rather than by losing money. Several of them
were inside the machinery that exists to keep this release's own numbers honest.

### The signal path

* **A strategy in the library could not vote long.** It scored its three stack conditions with
  `+` over numpy scalars, and `+` on numpy booleans is *xor*: the sum was always `True` or
  `False`, so the `score >= 2` branch was unreachable and the strategy returned a bearish vote
  on every instrument with 52 bars or more. Inside a consensus that is a permanent short bias,
  and it never raised an exception — it only voted. Of the 40 cached instruments long enough to
  fire it, 15 now produce a long vote where none was possible; mean net consensus moves +0.0475
  and one instrument changes sign. A test now walks the package's syntax tree for that sum
  shape, because no runtime error would ever have surfaced it.
* `kairos --version` answers instead of exiting 2, so a reader following a README link can
  confirm an install without a subcommand.

### The pack's own truthfulness

* The figures in `docs/investors/` were regenerated on every pass, while **the date printed
  beside them and the version named in the whitepaper were typed by hand** and had gone stale —
  under a footer claiming they were verified that day. Both are generated values now: the date
  comes from the ledger's own rebuild stamp, never the wall clock, so the pack cannot claim a day
  the evidence was not read. The new guard failed on five sites the first time it ran.
* **The figure guard never read the PowerPoint.** `docs/investors/KAIROS_Investor_Deck.pptx` is
  the copy that gets attached to an email, and because the rewriting command only touches text
  files it sat outside every check — and had gone further stale than the markdown beside it:
  ten sites, including a version stamp two releases behind. The deck is read as text now (a
  `.pptx` is a zip of XML, and its runs flatten into the vocabulary the rules already match).
  Three of those sites were missed by the first version of the check, because the stamp table
  only recognised `Version N.N.N` and `dated <date>` while a slide writes `KAIROS vN.N.N` and
  `verified against the repository on <date>` — a checker that knows one spelling reports a
  stale value as *absent* rather than wrong, which is the same failure mode as not knowing the
  word "passing". The check is read-only on purpose: editing run boundaries inside a binary is
  how a deck gets corrupted, so it names the value to rebuild with instead of fixing it quietly.
* Guarding the deck cost it two numbers. The journal grows every ten minutes, and a file nobody
  re-runs on that clock must not print a count it cannot keep current, so the slides now carry
  the figures that are stable inside a release and point at the dated ledger for predictions
  journaled and autopilot cycles.
* The rewriter matches on adjacency, so **it could not tell a live figure from history quoted
  inside the defect narrative** — and it had been quietly overwriting the numbers the
  whitepaper's own defect table cites as evidence of the earlier staleness bug. Those examples
  are written as patterns now.
* **The copy GitHub publishes was not in the repository.** The release note is where this pack
  makes its plainest claims, and it was written in a scratch file, pushed once, and read by no
  guard — which is where the pack's first false statement came from: a paragraph denying that
  any hit rate or return figure appears anywhere in the kit, sitting in a document that
  publishes a per-instrument net return and a per-trade hit rate, and promises a hit rate
  later. Release bodies live in `docs/investors/releases/` now, and a claim of absence is
  checked against the files it describes. Only a quantified denial can be refuted that way, and
  the narrowing word has to sit next to the noun it narrows — otherwise the clause that caused
  the denial, here that zero directional calls have matured, excuses the denial itself, which
  is how a false sentence read as true to the person who wrote it. The first version of the new
  check missed even this one: the note wrapped its line between the denial and its quantifier,
  and a checker that reads line by line reads a quantifier that is not there.
* Every remaining `E741` lint debt is gone: `python -m ruff check kairos tests tools` reports
  `All checks passed!` for the first time. The renames were proven value-neutral rather than
  assumed — the previous and current versions of each module were run against the same
  deterministic frames and compared key by key (78 feature fields, a 400-row panel, all 100
  strategy votes, zero mismatches).

**Corrected the day it was published.** An earlier version of this paragraph denied that any
hit rate, accuracy or return figure appears anywhere in the pack. That was false as written.
The track record attached to this release publishes a per-instrument net return and a
per-trade hit rate, and this note's own next section says a hit rate will be published once
the forward record exists. The sentence dropped the one word that made it true — *forward* —
and nothing in the suite noticed, because every existing check asks whether a quoted number
is right and none asks whether a claim of absence is. It does now.

**Zero directional calls have matured, so no forward hit rate, accuracy or realized return
appears anywhere in this pack, and none is implied here.** What the pack does publish is
evidence of a different kind, and it says so: the walk-forward sweep's per-instrument net
returns, Sharpe ratios and per-trade hit rates — including the six instruments that lost money
— and one realized paper figure, Rs -13.05 on two fills. Those are backtests and a paper book,
not a track record, and the finding that PSX equities are net-negative after local costs is on
the slide rather than in the appendix. This is not a fund, not a licensed adviser, and not an
offer of securities or of managed money.

## Verify it yourself

```
git clone https://github.com/zhaider5142009-oss/kairos && cd kairos
pip install -r requirements.txt
python -m pytest tests -q                     # 259 tests
python tools/make_track_record.py             # rebuild the ledger from the journals
python tools/kit_stats.py                     # the only figures this pack may quote
python tools/kit_stats.py --write             # re-point the pack at them
```

The deck attached here is generated from `docs/investors/DECK.md` and is checked against the
repository by `tests/test_kit_figures.py` before it ships.

**One note on v2.6.0:** the deck file attached to that release carried the stale figures
described above. Nothing about v2.6.0's code is affected by it, but the corrected deck is
attached here and v2.6.0's body has not been edited, so anyone who downloaded the earlier asset
has the file as it was.
