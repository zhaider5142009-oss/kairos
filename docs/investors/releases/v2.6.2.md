## What this release is

One correction, and the four defects in the guardrail that let it stand. v2.6.1 shipped investor
evidence that the repository no longer generates. v2.6.2 publishes the evidence the repository
does generate. It is worse, and it is the version that gets presented.

### The evidence moved, and what moved it

v2.6.1's ledger reported **8 of 14 instruments profitable**, a global book mean of **+13.6%** and
a PSX equity mean of **−2.8%**. Rebuilding the ledger now prints **5 of 14**, **+10.0%** and
**−2.2%**, and three instruments the deck showed as winners — BRENT, NATGAS, KSE100 — finished as
losses. Two causes, both verifiable in this repository:

* **The ledger read the wrong sweep log.** `_spectrum()` chose the widest walk-forward run by row
  count alone over a sorted glob. The run re-executed on 2026-10-21 produced fourteen rows — the
  same width as the 2026-10-17 run it replaced — and lost the tie on alphabetical order. So
  `python tools/make_track_record.py` was faithfully regenerating a table four days old, under a
  footer that said the figures were verified that day. Ties now go to the newest file, and the
  ledger names the log it read and the afternoon it ran, because a sweep is evidence with a
  vintage and the journal figures beside it are current to the minute.
* **That older run predates v2.6.1's own bug fix.** The strategy that could never vote long
  (`+` over numpy booleans is xor) was repaired before v2.6.1 shipped, but the sweep behind the
  8/14 headline was executed before the repair. The number an investor would have read was
  produced by code the same release admits was defective.

The instruments also disagree with the old table individually: WTI falls from +25.1% to +16.0% and
does not beat buy-and-hold, WHEAT rises from +19.5% to +26.8%, and OGDC, the largest loss, is
−14.3%. The row an investor should trust is the one the current code prints, which is what this
release attaches.

### The methodology sentence was wrong in every copy

v2.6.1's ledger described the sweep as "**100 candidate strategies per instrument**" and the deck's
cover repeated it. It is not the 100-strategy library. What the sweep actually fits, per
instrument, is one composite signal blended from 4 components, whose weights, entry threshold,
regime gate and short mode are chosen by a **2,592-point grid search** on a rolling 252-bar window,
re-fitted every 30 bars and traded only out-of-sample with PSX commission and slippage modelled.
That library votes inside the live engine, and none of the published returns come from it. The
ledger, the deck, the one-pager, the whitepaper and the landing page state it now.

### Four guard defects, found because the corrected evidence disagreed with the pack

* **A ratio was only read when the word "profitable" was glued to it.** The headline rule matched
  `N of M … profitable` and nothing else, so "profitable on 8 of 14 instruments", "6 of 14
  instruments in the walk-forward sweep lost money" and "8 of 14 instruments came out
  net-positive" were invisible to both the rewriter and the checker — three claims that every
  refresh pass left behind. A pair of numbers is now read as a sweep ratio by its denominator, and
  the word nearest it says which side it counts, so the loser count and the winner count are both
  checked and neither can be quietly refreshed alone. "24/7" and "5 / 8 GB" stay out of it on
  arithmetic: a real count cannot exceed its own total.
* **A book mean was only read beside the word "mean."** "+13.6% across the global book" survived a
  complete refresh cycle for the same reason — the venue, not the word "mean", was what made the
  number a mean. Binding a mean to the book it names also catches a figure written into the wrong
  sentence, which a set of allowed magnitudes cannot see.
* **Every rule here checked a number, and the pack's worst false claim was a noun.** "Walk-forward
  sweep, 100 strategies per instrument" sat on the cover of the deck through the whole refresh
  cycle, because the `100` beside it was verified as the strategy count. A sentence that credits
  the library with the sweep is now denied by `method_claims()`, in the same pass as the figures;
  a sentence that says "not" is the pack's own disclosure and is left alone.
* **Three files declare the version and only one of them is read by code.** Bumping
  `kairos/__init__.py` left `pyproject.toml` and `config.example.yaml` at 2.6.1, and
  `tests/test_smoke.py` failed the build instead of letting a tag disagree with `pip show kairos`.

The deck's own cover also had to be rebuilt by hand rather than rewritten: it is a binary, the
rewriting command touches text files, and the guard that reads it is read-only on purpose.

anywhere in this pack, and none is implied here.** What the pack does publish is evidence of a
different kind, and labels it as such: the walk-forward sweep's per-instrument net returns, Sharpe

a paper book, not a track record. The finding that PSX equities are net-negative after local costs

offer of securities or of managed money.

## Verify it yourself

```
git clone https://github.com/zhaider5142009-oss/kairos && cd kairos
pip install -r requirements.txt
python -m pytest tests -q                     # 286 tests
python tools/make_track_record.py             # rebuild the ledger from the journals and the sweep log
python tools/kit_stats.py                     # the only figures this pack may quote
python tools/kit_stats.py --write             # re-point the pack at them
```

`python tools/kit_stats.py` with no arguments prints the figure set and then either "pack claims:
consistent with the pack" or every claim in the pack — markdown, HTML and the PowerPoint included —
that the regenerated ledger contradicts. The deck attached here is generated from
`docs/investors/DECK.md` and is checked against the repository by `tests/test_kit_figures.py`
before it ships.

produced before the strategy repair, under a methodology sentence that describes a different
